# Colosseum 1.1.5

Colosseum 1.1.5 is the cumulative Windows release after 1.1.3. It carries forward the work prepared for 1.1.4 and adds the reliability, performance, privacy, security, and release hardening completed afterward. The v1.1.3 -> v1.1.5 range contains 173 commits.

## Read now, download later

Acquisition behavior is now consistent across Tankoban, comics, and Biblio. **Read** expresses consumption intent: Colosseum acquires what is needed and opens the reader as soon as the exact requested content is ready. **Download** is acquire-only and stops at Ready instead of unexpectedly opening a reader. Foreground read intent is guarded by identity and generation so an older request cannot hijack a newer session.

## Catalogues no longer live inside the installer

The installer no longer carries the large catalogue databases. On first launch Colosseum retrieves the anime/manga, Tankoban-volume, comics, and IMDb catalogue data into AppData from the public Colosseum-Data release. Shelves report honestly when a catalogue is still arriving and wake up as the data becomes available, while development checkouts can continue to use local databases.

This keeps the release package smaller while allowing catalogue data to evolve independently of the desktop binary.

## Tankoban acquisition and library work

Tankoban's manga acquisition path now uses a shared canonical volume-identity pipeline so source discovery, file selection, archive adoption, and the local volume index agree about which volume a release contains. The downloader gained stronger cancellation, recovery, image-host handling, archive ingestion, and durable indexing behavior, with expensive resume scans, image publication, recovery, and archive adoption moved away from the UI thread.

Volume progress is now included in Continue, and the catalogue also gained the One Piece color shelf. The western-comics side received richer catalogue-backed series data, source coverage, better empty/loading behavior, and more robust archive/download handling.

## Vault becomes a fuller local library

Vault's Browse surface now includes progress and Continue, watched/unwatched actions, in-place search and type-to-find, sorting and filtering, richer detail facts, keyboard/Escape navigation, and honest empty/error states.

Shows and seasons have stronger local presentation. Parsed years survive identification, enrichment can provide durations and local artwork, identified video can expose IMDb rating and genres, and media-bearing supplemental folders such as Bonus or OVA remain visible instead of collapsing into a generic season-zero bucket. Watched counts follow stable browse identity.

Storage controls were expanded too: roots can be rescanned or forgotten, scan-ignore patterns can be edited, Downloads entries can be removed, folder-aware counts are reported, and the library reconciles live filesystem changes more reliably.

## Theatre, streaming, and Player 1

Theatre series pages now use one scroll surface for the masthead and episode list. Anime see-all paging can use live Jikan/Kitsu results for current rows such as airing, upcoming, popular, and top-rated titles, with fallback behavior when live providers are unavailable.

Direct addon video sources now preserve required request-header provenance through download and playback handoff. Arriving playback can use the growing local partial file and then transition to the original HTTP source without losing the source headers needed by providers. Player 1 session/runtime recovery was hardened, and source/session routing was tightened so stale or unrelated media state is less able to leak across sessions.

If the bundled Stremio stream engine is missing or cannot start, Theatre now fails closed with a clear recovery message instead of remaining in a retry/switch loop. Requests queued during a failed engine startup are discarded so they cannot replay later against a repaired or replaced runtime.

## Reader, progress, history, and search

Reader 2 switching and progress ownership were hardened so a rapid A -> B content switch cannot mix a previous book's pending save or Continue metadata into the replacement session. Progress-store replacement is atomic and periodic progress writes remain quiet instead of generating unnecessary activity noise.

Consumption facts are projected into durable history more consistently, including automatic movie completion and Tankoban volume resumes. History retention now respects local privacy policy, and cross-device history synchronization honors category policy rather than treating every history category as universally portable.

Search/discovery also received lifecycle hardening: profile-local search-history preference is durable, search surfaces follow the current history owner, stale requests are cancelled more aggressively, duplicate debounced submissions are avoided, and provider failure is kept distinct from a legitimate empty result.

## Account and recovery hardening

The account client, recovery flow, and shell received another hardening pass. Remembered account identity can remain visible while offline, recovery password rules are aligned with the account policy, recovery-key acknowledgement is required before continuing, and hostile/stale authentication responses are handled more defensively.

This release still does **not** claim a public production account service. Account creation, sign-in, and cloud sync depend on a deployed service endpoint and are not presented here as generally available features. The repository contains the service, CI, and deployment groundwork, with the current deployment runbook targeting Google Cloud Run + Neon Postgres.

## Responsiveness work

A large part of the post-1.1.4 work focused on keeping the GUI thread free. Startup and Home work are staged after the shell becomes usable; hidden worlds stop doing unnecessary work; retained catalogue/library models are lifecycle-gated; stale catalogue work is cancelled; Vault and Downloads page construction is staged asynchronously; comic and manga archive probing/adoption, local-media admission, deletion cleanup, manga resume scans, image publication, and volume recovery were moved away from the UI thread where appropriate.

The result is less background work competing with navigation and interaction, especially during startup, world switching, downloads, and large local-library operations.

## Security and code-quality gates

The desktop pipeline now includes CodeQL, a clang-tidy correctness gate, AddressSanitizer probes, coverage-guided fuzzing, and dependency scanning. Fuzz targets exercise the CBZ/ZIP parser, Watch Party wire decoder, and update-manifest parser. Fuzzing also surfaced a concrete archive hardening issue: CBZ entries that declare an implausibly large uncompressed size are rejected before allocation, blocking that decompression-bomb/OOM path.

The Go account service is checked with reachability-aware dependency scanning. CodeQL and clang-tidy findings across native lifecycle, torrent, updater, and Watch Party code were also remediated during this release window.

## Windows packaging, updater, and release verification

The Windows installer bundles the complete Stremio stream-server runtime, uses Colosseum branding and iconography throughout installer/uninstaller UI, and carries the correct 1.1.5 version metadata. Silent uninstall registration supports package-manager removal paths, and Chocolatey packaging metadata now lives in-tree.

Updater handling received additional correctness work, including request/version cleanup and hash-verification lifetime fixes.

The release workflow builds from an exact master commit, validates the required runtime payload, fingerprints the installer, and performs a fresh Windows install, application boot, runtime-file check, and uninstall smoke test. The stream-engine failure path is also covered by a real Qt regression test and a static runtime contract.

## Repository and contributor surface

This release window also added the public contributor/security baseline around the application: CONTRIBUTING, SECURITY, SUPPORT, Code of Conduct, issue templates, a pull-request template, Windows build documentation, CI status/quality documentation, and stronger test/verification documentation.

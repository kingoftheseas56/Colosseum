# Colosseum 1.1.4

## Read now, download later

Every world's acquisition flow is now consumption-first. Pressing **Read** on a comic issue, a
Tankoban volume, or a Biblio book opens the reader as soon as the content can open, guarded so a
stale or superseded request can never hijack the session. Pressing **Download** acquires the content
and stops at Ready — it no longer flips into the reader on its own. The split runs through both of
Biblio's transports, through Tankoban's volume source picker, and through the comics ledger, so the
two intents finally mean the same thing everywhere.

## The catalogues fetch themselves

The installer no longer ships any catalogue database. On first launch, Colosseum downloads all four
catalogues — anime/manga, Tankoban volumes, comics, and the IMDb index — from the public
Colosseum-Data release into AppData. Shelves state plainly that a catalogue is still downloading and
wake up live as each one lands; a dev checkout with local databases keeps working unchanged. This is
also what keeps the installer's size down now that the catalogues have kept growing.

## Comics catalogue intelligence

Tankoban's western-comics side gains a real catalogue engine: enriched series data drives new
Discover shelves and a per-series ledger, and shelves degrade gracefully — an empty or
still-downloading catalogue renders an honest empty state instead of a broken wall.

## Tankoban volume identity

Volume acquisition adopts a Torrentio-style identity pipeline: one shared, string-safe volume
grammar interprets source listings, so the source picker and the file picker agree about which
volume a release actually contains — better matches, fewer misfiled downloads.

## Theatre polish

The series episode list now lives on a single scroll surface — the masthead and episode rows move
together instead of trapping the wheel inside a nested list.

## Runtime composition hardening

Pause/resume authority moved out of QML into the native session coordinator, and the Watch Party
bridge and update cache are now owned, composed services. Startup gains an explicit bootstrap
(AppData migration and startup layout), and pinned-host networking was reworked around a durable
IPv4 pin store with retrying resolution.

## Quieter installs, more channels

The installer now registers a quiet uninstall command, so `winget uninstall` (and any other silent
manager) can remove Colosseum without popping the uninstaller UI. Colosseum 1.1.3 was submitted to
the WinGet community repository as `Colosseum.Colosseum`, and a Chocolatey package definition now
lives in-tree — 1.1.4 flows to those channels from this release.

## Fixes

- The in-app updater's artwork fetch identified itself with a stale 1.1.1 User-Agent; all updater
  requests now report the current version.

## Known issues

- After dismissing the volume sources picker, Tankoban cards can be unresponsive for a few seconds
  before recovering (carried from 1.1.3; the picker flow was reworked this release but this issue has
  not been re-verified as fixed).

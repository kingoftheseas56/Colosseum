# Colosseum 1.1.6

Colosseum 1.1.6 is the cumulative Windows release after 1.1.5. This release window concentrates on keyboard-first navigation, multilingual Tankoban chapter sources, account/session durability, responsiveness, and release verification. The Windows installer remains the stable release artifact; Linux continues on its separate beta qualification track.

## Keyboard-first navigation

Colosseum now has an arrows-first spatial navigation model across the shell, worlds, catalogues, account surfaces, settings, readers, and player-owned controls. Directional navigation follows visual intent, keeps focus inside the current content owner, and continues through overflowing scrollable content instead of treating the viewport edge as a dead end.

Focus return, deferred landings, virtualized collections, carousel movement, overlay containment, key-repeat lifecycle, and release handling were hardened with Qt Quick and assembled-app runtime coverage. Enter remains the primary keyboard action, Escape backs out by one owned level, and Tab remains secondary traversal.

## Tankoyomi multilingual chapter sources

Tankoban chapter mode now supports persisted multilingual provider configuration and region-safe language routing. Provider identity, source matching, fallback ordering, attempt limits, HTTP transport, page-image transport, and network capability checks were tightened so a weak provider cannot silently broaden authority or replace a better source.

The qualification path now requires real image bytes rather than trusting URL-shaped responses. Metadata and image hosts also gained bounded IPv4 resilience for environments where broken IPv6 routes would otherwise make a healthy provider look unavailable.

## Account and sync durability

Remembered account sessions persist across normal launches, tagged test sessions are isolated from production credentials, duplicate desktop instances are prevented from racing refresh-token authority, and stale recovery approvals are invalidated more aggressively.

Cross-device state work now includes stricter sync admission and replay identity, crash-durable remote-owner writes, safer profile replacement, activity/history migration, and attachment/lifecycle recovery. Account operations still depend on a correctly configured service endpoint; the desktop fails closed rather than inventing local cloud state when that authority is unavailable.

## Responsiveness and startup

The responsiveness hardening program moved recurring work away from the GUI thread, reduced unnecessary hidden-world activity, tightened background-work scheduling, and added hard regression gates around known stall classes. Source launches also refresh their QML build manifest before startup so a valid native executable does not reject a freshly changed QML tree as stale.

The bundled Stremio runtime startup path was hardened again so Theatre can recover its stream server instead of remaining stuck behind a failed launch state.

## Release and CI hardening

Desktop CI now exercises a broader Windows and Linux build/test surface with compiler caching, platform-aware runtime dependencies, code-quality gates, and release-critical smoke coverage. The 1.1.6 release contract now binds the executable version and updater network identity to the same application version instead of allowing old hard-coded User-Agent strings to survive a version bump.

Windows clang-tidy findings in MangaDownloader's asynchronous cleanup and image-save paths were removed by using Qt 6 context-bound future continuations, preserving the existing cancellation and job-lifetime fences without heap-owned completion watchers.

## Windows packaging and verification

The release workflow builds the canonical installer from an exact trusted master commit, fingerprints the produced installer, and runs a fresh install/boot/runtime-file/uninstall smoke on a clean Windows runner. The executable, installer metadata, updater identity, release notes, and release presentation are all targeted at 1.1.6.

A release is not considered ready merely because an installer filename exists. The release gate requires the release-contract tests, Windows build and smoke targets, clang-tidy correctness gate, AddressSanitizer probes, and fresh-install workflow to succeed for the exact candidate commit.

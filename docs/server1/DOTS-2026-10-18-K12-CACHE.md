## Existing owners extended

EngineRegistry owns per-file first-open markers, monotonic missing-piece watchers
and the uncached-file counter. TorrentEngine exposes app-lane cache facts and
verified-piece notifications. Store destinations are obtained on its existing
work lane and copied into an immutable app-lane mirror. No new database, store,
worker pool or competing engine owner was introduced.

First-open cache initialization is deferred behind the current app turn, matching
the controlled M814-ready timing boundary. The synchronous active-event pair
precedes created/progress/cached events. Repeated opens do not recreate watchers.
Cache progress uses ceil(file length / virtual piece length) as its denominator;
a short cross-boundary file therefore reports -1,0,1 instead of being clamped.
Progress has no fabricated path; cached events use the actual optional store
destination. Circular storage exposes no destination.

The missing set only shrinks. Circular eviction changes live committed facts but
does not rearm completed cache events. Generation and shutdown checks stop stale
initialization and callbacks after removal, replacement or owner destruction.
The uncached counter supplies the source idle pair after its grace timer.

First-open persistent/unbuffered selection also admits real engine-owned demand.
It does not create a FileReader. Verification-group demand remains bounded by
physical geometry. M172's raw inclusive selection endpoints, including its
possible one-past-final-piece value, are retained separately for the forthcoming
statistics projection; that projection is NOT implemented by this checkpoint.
Background selections are excluded from reader-buffer swarm-cap inputs because
the source omits readFrom/selectTo for them. Existing reader selection behavior
is preserved.

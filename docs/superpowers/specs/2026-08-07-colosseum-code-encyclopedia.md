# Colosseum Code Encyclopedia — Design Specification

**Status:** approved design, locked by Hemanth 2026-08-07. Implementation not started.
**Owner:** Agent 0. **Authoring channel:** Preflight-Architect (drafts), Agent 0 (ground-truths and adopts).
**Home:** this repository. The encyclopedia lives in Colosseum, never in Preflight-Architect.

## Problem

Colosseum is 564 source files and 128,434 lines. An agent asked to work in an unfamiliar
subsystem has no way to learn which files matter without grepping blindly, and nothing at all
describes how files connect into a working flow. The existing `docs/superpowers/plans/` corpus
records what we *intended to build* on a given date; it is not a description of what exists now.

## Ground truth (measured 2026-08-07 at `master@a40333d`)

| Fact | Value |
|---|---|
| native headers / sources | 153 `.h`, 131 `.cpp` |
| QML files | 189 |
| test sources | 91 |
| total lines (native + qml) | 128,434 |
| QML files opening with an explanatory comment | **181 / 189 (96%)** |
| native headers opening with an explanatory comment | **78 / 153 (51%)** |
| `CONTEXT.md` glossary | 26 lines, ~8 terms |
| `docs/adr/` entries | 1 |

The decisive finding: **Colosseum already documents itself well inside the source.** The gap is
navigation, cross-file flow, and 75 silent native headers — not explanation.

## Product promise

An agent lands in an unfamiliar part of Colosseum and, in one lookup, learns which files matter,
how they flow together, and what will bite them — without reading 128k lines and without trusting
prose that may have silently rotted.

## The central rule

**The source is the single source of truth. The encyclopedia never outranks the code.**

Everything below follows from that rule. Where a document and the code disagree, the code wins and
the document is what gets corrected.

## Structure

### Layer 1 — Generated index (cannot drift)

- One entry per source file, **harvested from that file's own top-of-file comment**. Not rewritten,
  not paraphrased.
- **Never hand-edited.** Regenerated by a single command; edits belong in the source comment.
- Every entry is stamped with the file's **git blob hash** at harvest time.
- On regeneration, an entry whose blob hash no longer matches is marked **DRIFTED** — its
  description may predate the current code.
- A file with no top-of-file comment is listed as **UNDOCUMENTED** rather than omitted, so the gap
  is visible and countable instead of invisible.

Drift and absence are therefore *reported*, never silent. This mirrors the SHA-pinning discipline
already used for Preflight artifacts.

### Layer 2 — Subsystem guides (the authored layer)

Approximately 20 hand-written guides, one per subsystem — the unit an agent actually works in, and
one that changes far more slowly than individual files.

Each guide answers exactly these questions, in this order:

1. **What this subsystem is for** — one plain sentence.
2. **The flow** — entry point to exit, as it actually runs.
3. **The files that matter** and the role each plays (deep links into the generated index).
4. **Where state lives** — what persists, keyed by what.
5. **The traps** — what has burned someone here, with the evidence or commit that proved it.
6. **How to test it** — the existing harness or gate that covers this subsystem.

Guides are drafted by Preflight-Architect and **ground-truthed against live source by Agent 0
before adoption**. A guide may not assert a file, function, or behavior that has not been read.

### Layer 3 — Discoverability (thin, but load-bearing)

The index is reachable from where agents already look at wake: the memory lane index points to the
code map for that lane. An encyclopedia nobody opens is worth nothing, so its entry point is part
of the deliverable, not an afterthought.

## The write-back rule

**A brother who changes a subsystem updates that subsystem's guide in the same commit** — the same
discipline as declaring a shared-file edit. A doc system with no write-back path rots regardless of
how well it starts.

The generated layer needs no write-back: it is regenerated.

## Flows

**First use.** An agent wakes in a lane, reads memory, follows the pointer to the code map, and
opens the guide for the subsystem it was summoned into. It knows the flow and the traps before
opening a single source file.

**Normal use.** "Which file handles X?" → one index lookup → the file, with its own words about
itself.

**Drift.** An entry is marked DRIFTED. The agent treats the description as a hint, not a fact,
reads the source, and (if it is doing work there) the regeneration refreshes the entry.

**Gap.** An entry is marked UNDOCUMENTED. The agent reads the source, and if it is working in that
file it adds the missing top-of-file comment **to the source**, which the next regeneration
harvests. Gaps close as a side effect of normal work.

**Completion.** Work that changed a subsystem's behavior updates that subsystem's guide in the same
commit.

## Pilot scope

**Comics ingest and the reader path** — from a chosen comic through download, archive ingest, and
storage, to rendered pages in the reader. Chosen because it is the hairiest, highest-traffic code
in the app with the most proven traps (the CBZ-in-place two-path ingest and legacy migration), so
a format that survives here survives anywhere. Exact file membership is enumerated at
implementation time from the source, not assumed here.

The pilot ships: the generator, the generated index for the pilot subsystem, one subsystem guide,
the drift/undocumented reporting, and the discoverability pointer.

**The pilot is judged by an agent using it on a real task** — not by its own completeness.

## Acceptance criteria

1. One command regenerates the index; running it twice with no source change produces no diff.
2. Every pilot-subsystem file appears in the index, each carrying its own top-of-file comment,
   its blob hash, and its path.
3. A file with no top comment appears as UNDOCUMENTED, and the total count of such files is
   reported.
4. Editing a source file and regenerating marks that entry DRIFTED until its comment is re-harvested.
5. Hand-editing a generated entry is either rejected or overwritten on regeneration — the generated
   layer cannot be quietly forked from source.
6. The subsystem guide names only files, functions, and behaviors that exist at the stated commit.
7. The guide states where the subsystem's state persists and which harness covers it.
8. An agent starting cold on a real comics task reaches the right file using only the encyclopedia,
   and says so.
9. The index is reachable from the wake path without prior knowledge that it exists.
10. No entry in the generated layer restates or contradicts the source comment it was harvested from.

## Non-goals

- A page per file. Explicitly rejected (see below).
- Documentation of third-party or vendored code.
- API reference material generated from signatures — the source already carries that, and it reads
  better in the editor.
- Prose written for Hemanth. The audience is agents; he should never need to read it.
- Reviving the architecture-decision record practice. Related, separate, deferred.
- Any rollout beyond the pilot subsystem before the pilot is judged.

## Discarded alternatives

**A page per file (564 pages).** Rejected: with many brothers pushing to master continuously,
hand-written prose about 564 files drifts within weeks, and a stale document is worse than none
because an agent trusts it and acts on it — the precise inverse of the ground-truth-before-claim
rule. It also duplicates comments that already exist in 96% of QML files and 51% of native headers,
and two copies of one truth guarantees that one of them is wrong.

**Source comments only, no authored layer.** Rejected: it is drift-proof and does close the 75-header
gap, but nothing then explains how files connect, which is the agent's actual question. Its best
idea — fix the source rather than describe it from outside — is absorbed into the UNDOCUMENTED
reporting and the gap-closing flow above.

**Hosting the encyclopedia in Preflight-Architect.** Rejected: the write-back rule requires docs and
code to move in one commit, the generator must run against this source tree, and blob-hash stamping
compares against this repository's objects. Preflight authors; Colosseum hosts.

## Deferred

- Rollout to the remaining subsystems, pending the pilot verdict.
- Backfilling all 75 silent native headers as a dedicated sweep; for now they close opportunistically
  as agents work in them.
- Reviving `docs/adr/` (1 entry today).
- Any automated enforcement of the write-back rule.

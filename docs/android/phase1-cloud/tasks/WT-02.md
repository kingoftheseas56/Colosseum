# WT-02 — Account forms lost explicit keyboard avoidance and focused-field reveal

Class C; priority P2. Authorization/order comes from START.md, not classification alone.

## Why this matters
Lower form fields/actions can become covered when real keyboard consumes height; actual effect depends adjustResize/density/IME geometry. No device failure inferred solely from removal.

## Alpha behavior
SettingsScaffold computes keyboard overlap and AccountPageFrame tracks focused text, reserves inset/scroll extent and reveals fields even if an IME reports no rectangle.

## Beta behavior
AccountPageFrame is Item with fixed scroller bounds and content extent; no keyboard/focus reveal mechanism. Android secure storage remains implemented; this is presentation/IME reachability risk.

## Actual owner/caller
Main AccountOnboarding -> AccountSignIn/Create/Recovery/DeviceApproval -> shared AccountPageFrame. Sign-in/create fields remain active on Android; native OS resize may mitigate, but not prove focused field visibility.

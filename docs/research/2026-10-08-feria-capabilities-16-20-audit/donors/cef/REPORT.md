# CEF source/API audit: categories 16–20
## Result
Keep Colosseum’s existing media, profile-download and metadata owners. CEF provides useful lifetime/state-machine comparisons, but none of the inspected internal components is a justified direct copy into QtWebEngine. It is not a recommendation to add another engine.
The most important rejection is CEF’s **silent orphan transfer** behavior: a source browser can close without cancelling its transfer, but CEF stops calling its browser-scoped download handler. The product needs both transfer survival and continued profile-level observability. Also reject destination fallback as proof of user consent, programmatic URL downloads as an exact subframe Save replacement, and OSR hiding/audio mute as app-owned media pause.

## 16. Pause on app minimize/world-away; resume only media paused by Colosseum
**Evidence:** source_traced; dedicated app-owned pause/resume API absent in inspected CEF surface; behavior reference only. **Classification:** Keep existing Colosseum implementation; adapt donor frame retirement behavior into existing Colosseum owner; internal reference only.
**Ownership/API path:** Host visibility/mute → WebContents/OSR presentation. CefFrame script API → frame-scoped Mojo message → Blink ExecuteScript. The app must own exact space/document/frame/media identity, pause reason and resume acknowledgement; CEF supplies no Colosseum provenance ledger.
### Findings
- Mute is not pause: it invokes WebContents::SetAudioMuted only. WasHidden documents stopping layout/OnPaint for windowless rendering and is not implemented by ChromeBrowserHostImpl.
- Frame commands carry an actual CefFrame association, are ignored for temporary/detached frames, queue until connection, and discarded on full detachment. Frame identity is not by itself document identity; same-origin reuse is explicit in tests.
- CEF ExecuteJavaScript is void, with no playback-result acknowledgement or user-gesture grant. Cross-origin frames can be separately addressed by CEF frame APIs; that is not same-origin DOM traversal and is not a Qt API. No promise for arbitrary players, closed shadow trees, protected media, or default autoplay success.

## 17. Download request ownership and admission
**Evidence:** public API and internal ownership/source-retirement paths traced; source-only. **Classification:** Keep existing Colosseum implementation; adapt donor behavior into an existing Colosseum owner; internal reference only.
**Ownership/API path:** CefRequestContext → CefBrowserContext/Chrome Profile → content::DownloadManager → CEF delegate → originating browser CefClient::GetDownloadHandler. The profile owns transfer machinery, but the public handler is client/browser-scoped rather than a profile-level subscription.
### Findings
- CanDownload is synchronous admission for user-initiated navigation/click downloads; programmatic StartDownload is not covered by it. OnBeforeDownload receives the native item and one-shot destination callback; item wrapper is detached immediately after callback and must not be retained.
- Delegate captures DownloadItem→originating-browser once from DownloadItemUtils::GetWebContents, avoiding retargeting when navigation removes the WebContents relation. Source frame/origin is not included in the CEF download handler signature, and GetURL is a transfer URL, not request-origin proof.
- Continue consumes its download ID; callback work holds a weak manager, looks item up by ID and rechecks IN_PROGRESS after filename work. ResetManager invalidates outstanding weak pointers. Status updates may precede OnBeforeDownload.
- Suggested names go through net::GenerateFileName. An explicit path may create directories; directory-creation failure clears it and falls back to temp/current-directory plus suggested name. show_dialog cannot be treated as unconditional consent enforcement: if no source browser is recoverable, ChooseDownloadPath runs the suggested path directly.
- File-dialog callbacks have explicit release-to-cancel semantics, and a native dialog cancellation returns empty path. A stale dialog delegate result checks active_listeners_ before touching the listener; browser destruction destroys file-dialog manager before notifying download observers.
- Off-the-record context isolation is separate from transfer admission and separate again from app metadata authorization. CEF has no one-use Feria metadata-grant concept. Same nonempty cache path or explicit CreateContext(other) shares context/storage.

## 18. Download progress/pause/resume/cancel/open
**Evidence:** native state projection and action implementations traced; paused/resumable/open surface incomplete. **Classification:** Keep existing Colosseum implementation; adapt donor behavior into an existing Colosseum owner; internal reference only / unsupported public operations.
**Ownership/API path:** DownloadItem native state → temporary CefDownloadItem snapshot → host copied projection; separate retained CefDownloadItemCallback resolves manager+ID on UI thread at action time.
### Findings
- Public states distinguish IN_PROGRESS, COMPLETE, CANCELLED, INTERRUPTED and interrupt reason; bytes, rough percent, speed, times and actual full path are available. PercentComplete is documented as -1 for unknown total, not a completed/zero-byte inference.
- Cancel and Pause post to UI then act only if item still IN_PROGRESS; Resume posts then checks native CanResume. Cancel resets callback download_id to zero. A completion race cannot be converted into cancellation by these methods because they recheck native state.
- The complete public CefDownloadItem interface contains no IsPaused, CanResume, CanOpenDownload, external-file-exists, OpenDownload or ShowDownloadInShell member at this pin. Resume support exists internally but cannot be advertised as a guaranteed public capability from the CEF snapshot.
- Interrupted-item Cancel through this callback is a no-op (IN_PROGRESS guard), while Resume can act if native CanResume. Action methods return void, so host needs fresh state/outcome rather than optimistic UI mutation.
- cefclient only shows a completion alert with GetFullPath; it does not validate or open a saved file. Native completion and current file availability must remain different state.

## 19. Download persistence and private cleanup
**Evidence:** CEF context/transfer retirement traced; persistence traced in shared targeted Chromium dependency; no CEF restart-resume API. **Classification:** Keep existing Colosseum implementation; adapt donor behavior into an existing Colosseum owner; shared Chromium internals reference only.
**Ownership/API path:** Source browser can retire independently of DownloadItem. CEF nulls browser association and suppresses callbacks; retained BrowserContext/RequestContext must outlive valid dependent transfers. Chrome Profile owns DownloadCoreService and persistence; off-record excludes DownloadHistory. Colosseum metadata grant/history is a separate app authority.
### Findings
- OnBrowserDestroyed deliberately does not cancel the DownloadItem, but nulls browser mapping: transfer continues silently until complete or browser-context destruction. A stale comment at GetOrAssociateBrowser lines 459–460 says cancel; the actual implementation at 423–433 governs this finding.
- Last CefRequestContext removal triggers browser-context shutdown; Chrome off-record context destroys its unique OTR Profile. A browser holds a request-context reference, but a download callback only holds a weak manager, not a keep-alive grant for that context. Closing the final source without another retained context can retire the dependency.
- CEF download public API has no enumerate/restore history or durable restart-resume facility. Its Chromium integration creates DownloadHistory only when !profile->IsOffTheRecord. That storage exclusion is not a promise to delete files saved to an explicit destination.
- Shared Chromium DownloadHistory distinguishes NOT_PERSISTED/PERSISTING/PERSISTED, uses weak callbacks, handles remove-while-add, ignores vanished manager/item and returns failed insert to NOT_PERSISTED for next-item-update retry without an immediate loop.
- Shared Chromium separates ordinary history (terminal/save-package rows) from in-progress DB. Reconstructing native downloads uses GUID, URL chain, storage partition, paths, validators, bytes and slices, not the lightweight Colosseum history row. Metadata alone is not restart-resume.

## 20. Save page/link/image/media through native download pipeline
**Evidence:** CEF Chrome/Alloy differences and native request/context paths traced; no uniform CEF Save API. **Classification:** Use a supported public engine API in receiving Qt adapter; adapt donor context-capability/lifetime behavior into existing owner; CEF/Chromium internals reference only.
**Ownership/API path:** Chrome-style native context-menu callback retains Chromium RenderViewContextMenu ownership/snapshot and executes native save commands. Link saves create DownloadUrlParameters for actual source RFH and browser-context DownloadManager; image/media saves use actual frame SaveFrameWithHeaders/SaveImageAt; page save enters WebContents::OnSavePage. Programmatic CefBrowserHost::StartDownload creates a main-frame request. Alloy default context menu has no Save page/link/image/media implementation.
### Findings
- Prefer native context snapshots/commands over interpolated script URLs. CEF params are borrowed callback-scoped; GetUnfilteredLinkUrl is explicitly copy-address-only and not validated for navigation/download.
- Chrome context callback is single-consumption; dropping it cancels, it binds a weak observer, and model/params/browser state is cleared on close. Its callback-facing GetFrame falls back to main frame after originating frame disappears, but native Chromium save operations retrieve/check the captured RenderFrameHost; do not adopt fallback as permission to retarget.
- Chrome link save checks surviving RFH and passes frame process/routing IDs, referrer policy, charset, initiator, suggested filename, prompt=true and CONTEXT_MENU source into the same browser-context manager. At this Chromium pin initiator is derived from frame_url with an upstream TODO to use actual origin: do not upgrade it into stronger proof.
- Image/media capability checks distinguish image contents, supported protocol and MediaCanSave; canvas/large-data image uses SaveImageAt, normal image/media passes source frame/referrer/headers to SaveFrameWithHeaders. PDF/print-preview paths are build/feature conditional.
- Chrome-style generic ExecuteChromeCommand is supported, but SavePage ultimately targets its Browser active WebContents. It is not a safe substitute for a captured inactive-page context ticket without validating the target.
- Alloy CanExecuteChromeCommand returns false and ExecuteChromeCommand is NOTIMPLEMENTED; its default menu switch has no save cases. ## Comparison dimensions and accepted/rejected choices

- **Correctness and originating target:** accept capturing source and native ID before mutable selection changes; reject routing through whichever browser/frame is now active. CEF main-frame StartDownload and Chrome active-tab Save commands are not exact-source-frame save tickets.
- **Async lifetime:** accept one-shot callbacks, native-state rechecks, weak manager/observer references, invalidated queued actions and late-result discard. Reject a callback-facing main-frame fallback as new authorization. Native transfer lifetime and source-document lifetime differ.
- **Privacy/account isolation:** accept explicit shared-versus-isolated request contexts and off-record history exclusion. Keep app account and metadata grants in FeriaAccountStore. Incognito storage is not an erasure policy for user-saved files.
- **Concurrency:** the profile manager and stable DownloadItem IDs permit multiple items, but client callbacks are browser-scoped. The inspected fixtures do not prove concurrent origins/windows, account swaps, or all asynchronous dialog races; these remain receiving fixtures.
- **Cancel/retry:** native state wins at action time. Do not turn cancelled into completed, assume interrupted is resumable, or claim `Cancel` succeeded when CEF’s IN_PROGRESS guard rejects it. For metadata, retain the existing app retry semantics, distinguish rejection from transient write failure, and guard late completion/removal.
- **Footprint/resource cost:** profile callbacks and copied projections are small. A CEF engine distribution, Chrome UI/profile services or Blink IPC transport is a large new runtime/build surface. No measured CPU/memory claims are made.
- **Portability/maintenance:** supported receiving Qt APIs are preferred. CEF API versioning, Chrome versus Alloy and optional PDF/printing capability matter. CEF/Chromium internal source copies would require engine integration and recurring revision maintenance.
- **Selected:** keep current Colosseum core; adapt immutable origin capture, request/callback expiry, transfer/profile dependency lifetime, typed action results and context capability tests where not already present.
- **Rejected:** embedding CEF automatically; copying its browser-client observer topology; inheriting silent orphan update loss; using temp-path fallback as destination consent; direct copy of DownloadHistory; ad hoc downloader or interpolated script URL scraping; global autoplay bypass; claiming hide/mute/freeze proves pause.

## Existing versus proposed receiving boundary

Existing authority is SessionStore identity, FeriaPlayback’s per-element ledger, FeriaSessionDeck profiles, FeriaBrowserDownloads request entries, and FeriaAccountStore grants/history. The CEF comparison does not authorize a replacement store. The following are semantic proposals for the prototype phase, not implemented APIs:

- An admission record extends the current request entry with immutable account/profile/space/document identity, best available native source view/frame identity, native transfer ID, request URL, privacy mode and separate destination decision / metadata grant.
- A transfer action takes an opaque transfer handle plus an action enum; it revalidates live native state and reports accepted, already-terminal, unsupported or retired instead of changing state optimistically. A finished-file handle resolves only through the trusted native owner after existence and authorization checks.
- A profile-retirement barrier counts outstanding consent/file dialogs and valid live transfers independently of views; account revocation explicitly cancels/drains or reports unresolved retirement. Source-tab close removes document-bound permission without destroying a valid profile-owned transfer.
- A Save capability snapshot binds the actual originating page/document/frame and native context ticket. Accepted Save reaches the existing profile pipeline; navigation/frame destruction/menu replacement consumes or invalidates the ticket. Unsupported formats/contexts stay disabled.
- A media command carries the existing document/element identity plus app-pause reason and result. Resume is authorized only for that surviving owned pause; user-paused media and ordinary inactive tabs keep their existing behavior. Freeze stays optional and separately gated on in-flight native work.

No CEF class above becomes callable through Qt. Exact receiving public API/version decisions belong to the QtWebEngine cell. Shared semantics remain separate from Qt/WebView2 adapters; this audit does not establish WebView2 parity.

## Decisive prototype fixtures suggested by the CEF evidence

1. Start simultaneous transfers in A/B spaces/windows sharing one profile; switch selection/navigation, and verify stable source/account binding and exactly one admission each. Negative control: resolve source from selected space at callback time.
2. Delay destination work, destroy source document/browser, retire profile, then release/replay callback; verify no use-after-free, unintended temp save, current-selection retarget or double admission. Negative control: omit lifetime/one-shot checks.
3. Close source tab after acceptance while another owner retains the profile; continue receiving progress and final state. Repeat for the last private tab and an explicit account switch. Negative control: use CEF-style silent observer loss or destroy profile on view-count zero.
4. Exercise unknown and zero totals, interrupt resumable/nonresumable, pause/resume races and completion versus cancel. Only native final state is authoritative. Negative control: optimistically mark action outcome as completion/cancellation.
5. Delete/replace completed file, switch account, replay a stale transfer/file handle and supply a renderer path. Open/Show must reject unauthorized or unavailable targets. A persisted history row is not file authority.
6. Fail metadata write and then retry with same valid grant; revoke/switch account before retry; remove while write completion is delayed. Verify once-only successful grant consumption and no stale-history resurrection. Do not copy the Chromium database to get this behavior.
7. Save page/link/image/media from native context in an iframe, then change focus/navigation before confirming; stale ticket rejects. Cover allowed and policy-disabled URL, image without contents, media lacking CAN_SAVE, canvas/large-data image, destination cancel, unsafe suggestion, supported page formats and actual output bytes.
8. Pause media for app-away/minimize with two media elements, one user-paused and one app-paused; same-origin navigation, cross-origin frame replacement, DOM/media source replacement and autoplay rejection must not revive unrelated playback. Negative control: mute/hide/toggle or a frame ID without document generation.

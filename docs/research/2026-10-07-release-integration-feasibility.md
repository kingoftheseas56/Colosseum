# Colosseum next release integration feasibility

Audit date: 7 October 2026. Phase: feasibility only. No integration implementation is authorized by this report.

The recommended release adds a narrow native AniList tracker and, subject to explicit gates, selected video sources and a Nuvio export importer. It rejects arbitrary CloudStream/Aniyomi execution, current StreamPlay parity and general continuous Nuvio mirroring. Phisher publishes v686 binaries without the corresponding source in the inspected master. Historical v366 remains aggregate complexity evidence; the user-supplied Arc 61 draft PR additionally provides a concrete v529-derived DahmerMovies Stremio HTTP adapter. That bounded subset is CONDITIONAL, with live playback and UI qualification still unverified. Existing Stremio and Trakt paths should remain their owners.

## Native source architecture

Selected sources should feed the existing Theatre source list through a small native provider seam. The useful contract is a capability descriptor, optional source search/detail/episode lookup, and asynchronous stream resolution for an explicitly mapped title and movie/episode key. Results contain direct URL or torrent identity, provider ID, label/quality, request headers, expiry when known, and subtitle descriptors. Requests carry cancellation, deadline, active-profile generation and provider configuration. Keep source-specific opaque lookup keys separate from canonical title IDs.

The minimum first adapter need not implement a foreign catalogue. Prefer existing Colosseum discovery plus an exact external-ID lookup. When only source-title search is available, expose a match selection and persist its source mapping; do not silently equate the first search result with the canonical title. Source-only catalogue browsing should be added only where an admitted provider requires it.

Share extraction helpers only after two admitted adapters need the same operation: bounded HTTP, HTML parsing, redirect resolution, HLS metadata, subtitle normalization and a specifically supported embed format. A shared resolver must declare hosts and supported versions. It must not execute arbitrary fetched JavaScript or Kotlin, replay foreign scripts with unrestricted network access, or grow into a second generic source ecosystem.

Native provider rows should reuse ExtensionsStore enablement, ordering and configuration. Provider secrets stay in profile-bound native credential storage, outside Store manifests, account sync and logs. Bound concurrency and response sizes; validate schemes, redirects and destinations; keep cookies isolated to provider/profile and restrict header forwarding across origins. A source failure returns a partial/empty result with a useful reason while other sources remain usable. Cache metadata and mappings, not expiring stream URLs as if they were durable media identities.

Upstream provider changes become explicitly owned Colosseum changes: pin the inspected revision, record the supported behavior, retain fixtures and attribution, and update on a reviewed cadence. Distribution of curated adapters is distinct from importing every entry in an upstream repository. This architecture captures selected-source value without an Android runtime, JVM class loader, new player or second progress store.

### API and authentication evidence

Official documentation was checked against [AniList/docs revision 03281c0a4bbf0c7f2097e0c935cddaed1096aa65](https://github.com/AniList/docs/tree/03281c0a4bbf0c7f2097e0c935cddaed1096aa65). Some rendered documentation URLs rejected fetches; the corresponding official raw Markdown at that revision was inspected directly.

AniList documents access tokens valid for about one year, no refresh tokens and no granular scopes. A public desktop binary cannot keep a client secret confidential. The supported public-client choices are implicit grant with a registered callback or the documented auth-pin/manual-token route. Start with the latter if it avoids adding a fragile callback transport. Verify the token using an authenticated Viewer query before binding the account; treat decoded JWT expiry as scheduling information, not proof of identity. Expiry or authentication rejection requires reconnecting, not a fake refresh request. [Authentication](https://docs.anilist.co/guide/auth/), [authenticated requests](https://github.com/AniList/docs/blob/03281c0a4bbf0c7f2097e0c935cddaed1096aa65/docs/guide/auth/authenticated-requests.md).

Implicit grant puts the token in the callback URL fragment. A plain loopback HTTP listener does not receive that fragment; the existing MAL code-grant listener is therefore not a drop-in AniList controller. A custom URI callback must preserve the fragment, reject unsolicited/stale callbacks and bind one active attempt. State echo/return behavior needs an actual registered-client check; it is not established by the short official examples. Authorization code exchange requires a confidential server secret; do not embed that secret in Colosseum or assume undocumented PKCE support. The auth-pin path provides a smaller initial architecture. [Implicit grant](https://docs.anilist.co/guide/auth/implicit), [authorization code grant](https://github.com/AniList/docs/blob/03281c0a4bbf0c7f2097e0c935cddaed1096aa65/docs/guide/auth/authorization-code.md).

Change vault validation narrowly to admit an access-only AniList credential with expiry and documented no-scope semantics while preserving the existing providers' checks. Never manufacture refresh tokens or pretend an internal capability marker is an OAuth scope. Add the controller/client/runtime to ProfileStoreRuntime and TrackerConnectionRouter, gate availability on registration and vault availability, and reuse connection generations and lifecycle handling. Local disconnect fences callbacks, pauses/discards work according to existing user choices and removes the native credential. No documented programmatic revoke endpoint was established in the inspected auth docs: label server-side revocation separately and direct the user to AniList's authorized-app controls rather than claim local deletion revoked the token remotely.

### Lists and identity

Read anime and manga separately using the authenticated user's verified numeric ID. MediaListCollection includes custom-list groups, so deduplicate by list-entry/media identity and retain entries hidden from default groups. The documented collection cap is 11,000 unique entries; do not label a capped or interrupted response a complete account import. Paginated fetching should use `hasNextPage`, not unreliable totals/last-page fields. Keep media ID, list-entry ID and user ID distinct. [Media-list queries](https://docs.anilist.co/guide/graphql/queries/media-list), [pagination](https://docs.anilist.co/guide/graphql/pagination).

Use stored AniList identity first. The official Media query supports `idMal` and media type, providing an exact crosswalk for a confirmed MAL anime/manga ID. Title search supplies candidates, not identity proof. IMDb/TMDB show IDs often span seasons while AniList entries split cours, specials and formats; an exact title mapping still needs a unit-range mapping before writing progress. Persist both through existing identity/mapping owners, with explicit ambiguity and unsupported states. [Query reference](https://docs.anilist.co/reference/query), [Media reference](https://docs.anilist.co/reference/object/media), [media identity guidance](https://docs.anilist.co/guide/graphql/queries/media).

The API supports consumed-unit `progress`, volume counts, status, score, repeat and fuzzy dates. Only progress/completion and preserved provider-list state are admitted here. Keep unrelated fields out of mutation payloads. Fetch and retain the returned list-entry ID for subsequent updates; read back after an unknown response before replaying a write. [Mutation reference](https://docs.anilist.co/reference/mutation), [MediaList reference](https://docs.anilist.co/reference/object/medialist).

| AniList status | Initial Colosseum interpretation |
|---|---|
| CURRENT | Active list state; eligible for explicitly mapped completed-unit updates. |
| PLANNING | Planned list state; zero consumed units does not imply an opened Continue record. |
| COMPLETED | Provider completion evidence; import through review without inventing local History/Activity. |
| PAUSED | Preserve provider status; do not silently resume because unrelated local metadata was accessed. |
| DROPPED | Preserve provider status; require deliberate export intent to change it. |
| REPEATING | Preserve repeat context; ordinary local replay must not reset progress or increment repeat. |

These statuses come from the official [MediaListStatus contract](https://docs.anilist.co/reference/enum/medialiststatus). There is no complete equivalent status field in the current generic progress journal; preserve them in the provider snapshot rather than distort the canonical fraction/completed model.

### Conflicts and delivery

Use existing TrackerImportStore classifications and explicit KeepColosseum/UseProviderProgress decisions. Keep the last observed provider snapshot and local revision binding. Import does not automatically enable export, and imported state must not echo back as locally witnessed progress. Remote advancement, local advancement, a remote reset and a repeat cycle are different cases; neither timestamps alone nor unconditional maximum-count merging solves all of them. Recheck connection generation, mapping and durable local facts before sending. For gaps in episode/chapter numbering, publish only a justified contiguous consumed-unit count or require reviewed user progress; completing episode 8 does not prove episodes 1–7 were consumed.

Keep local use offline. Cache a private provider snapshot and queue only eligible operations in the existing delivery journal. On reconnect, refresh the mapped remote entry before replaying an old operation that may overwrite a newer edit. Coalesce superseded progress writes while retaining review/receipt bindings. Mutation HTTP success is insufficient: inspect GraphQL `errors`, expected data and acknowledgement identity, including HTTP 200 error responses. [GraphQL errors](https://docs.anilist.co/guide/graphql/errors).

The published normal limit is 90 requests/minute, with a current degraded-limit warning of 30 and additional burst limiting. Schedule conservatively, honor actual rate-limit headers, `Retry-After` and reset time, use bounded exponential backoff with jitter, and stop on auth failure. Do not pool every desktop user through a server merely to centralize ordinary GraphQL traffic. [Rate limiting](https://docs.anilist.co/guide/rate-limiting).

The terms prohibit backup/data-hoarding use and competing non-complementary tracker services; commercial licensing applies above the documented revenue threshold. A local player/reader updating the user's AniList list appears complementary, but that classification is an inference, not provider approval. Resolve it for Colosseum's actual distributed product before announcing unrestricted support. Avoid bulk catalogue cloning or treating AniList as Colosseum's cloud backup. [API terms](https://docs.anilist.co/guide/terms-of-use).

### AniList implementation slices

1. **Credential and registration slice.** Add access-only credential validation, provider gating and a profile-bound controller using the documented public-client path. Verify wrong-account token rejection, expiry, cancel, reconnect, profile switch and local disconnect. Regression-check existing provider credential validation. Registered-client login remains a live acceptance check.
2. **GraphQL transport slice.** Native query/mutation DTOs, bounded responses, API error interpretation and shared scheduler. Verify HTTP 200 errors, partial data, 401/429/5xx, limits, deadlines and cancellation with transport fixtures.
3. **List snapshot and import slice.** Separate anime/manga reads, custom-list deduplication, completeness and provider status preservation. Connect to existing import review. Verify empty/private/large/interrupted lists and idempotent restart; do not invent Continue records.
4. **Identity and unit slice.** AniList IDs, type-checked MAL crosswalk and explicit candidate/unit mapping. Verify duplicate titles, cours/specials, absent MAL IDs, decimal chapters, reordered episodes and mapping changes.
5. **Progress delivery slice.** Completed-unit aggregation, reviewed first export, completion rules, durable outbox and unknown-outcome readback. Verify missing units, stale remote edits, auth expiry, offline restart and import/export echo suppression.
6. **Lifecycle and platform acceptance slice.** Existing tracker UI/routing, preservation on disconnect and Linux vault only if admitted. Verify two profiles against a dedicated test AniList account on each supported OS; repeat/rating/date fields remain unchanged. Distribution requires the registration/terms gate above.

## Aniyomi

### Arbitrary extensions

**Full Aniyomi extension/repository execution: NO-GO.** Colosseum can translate useful selected sources, but should not ship a general APK host in this release.

The inspected application revision is [aniyomiorg/aniyomi 97414446b8a95994c72dd33c41c971a89d4d25b8](https://github.com/aniyomiorg/aniyomi/tree/97414446b8a95994c72dd33c41c971a89d4d25b8). The official extensions repository is archived; representative maintained sources were inspected in [yuzono/anime-extensions 212743bb47c364de32ecbd0e0bcfc766815a71fd](https://github.com/yuzono/anime-extensions/tree/212743bb47c364de32ecbd0e0bcfc766815a71fd). This is a specific third-party repository, not a promise covering every unofficial repository. [Official extensions transition](https://aniyomi.org/news/2024-07-05-extensions-removal).

Aniyomi extensions are APKs containing Android metadata/resources, DEX classes and signatures. Android PackageManager discovers installed packages or private `.ext` archives. The current anime loader accepts API library versions 14, 16 and 17, trusts signatures, and instantiates classes/factories using ChildFirstPathClassLoader with PathClassLoader fallback. This is host-process executable code loading, not remote Stremio data. A trusted signature establishes provenance rather than limiting what the source can execute. [AnimeExtensionLoader.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/app/src/main/java/eu/kanade/tachiyomi/extension/anime/util/AnimeExtensionLoader.kt), [trust handling](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/app/src/main/java/eu/kanade/domain/extension/anime/interactor/TrustAnimeExtension.kt).

Repository discovery includes legacy JSON indexes and newer JSON/protobuf stores, compression, signing-key metadata and APK URLs. Parsing those feeds is a small distribution feature; executing their packages is the expensive missing runtime. Update/version/trust behavior must also follow package identity and API compatibility. [AnimeExtensionStoreService.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/data/src/main/java/mihon/data/extension/anime/service/AnimeExtensionStoreService.kt).

The effective host includes OkHttp, Android cookies, a main-thread Android WebView Cloudflare flow, preferences, dependency injection, RxJava/coroutines, Jsoup and native QuickJS. Individual sources can introduce activities, HTTP servers and browser interceptors. Replacing only Kotlin syntax or providing a JVM does not supply these semantics. [NetworkHelper.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/core/common/src/main/java/eu/kanade/tachiyomi/network/NetworkHelper.kt), [CloudflareInterceptor.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/core/common/src/main/java/eu/kanade/tachiyomi/network/interceptor/CloudflareInterceptor.kt), [ConfigurableAnimeSource.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/source-api/src/commonMain/kotlin/eu/kanade/tachiyomi/animesource/ConfigurableAnimeSource.kt).

Anime and manga interfaces are distinct. Anime models discovery, episodes, hosters, videos and lazy resolution; Video carries headers, tracks, timestamps, opaque internal data, mpv argument pairs and potentially local server URLs. Manga models series, chapters and pages and has a separate loader. Tankoyomi can express selected manga behavior but cannot stand in for the complete anime API. Arbitrary extension-provided mpv options and local servers should not become trusted player configuration. [AnimeSource.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/source-api/src/commonMain/kotlin/eu/kanade/tachiyomi/animesource/AnimeSource.kt), [Video.kt](https://github.com/aniyomiorg/aniyomi/blob/97414446b8a95994c72dd33c41c971a89d4d25b8/source-api/src/commonMain/kotlin/eu/kanade/tachiyomi/animesource/model/Video.kt).

Desktop subset execution is possible. [Miwayomi revision a3a776ebd26f91f558cd59a4bd57fff9119ee987](https://github.com/miwayomi/miwayomi/tree/a3a776ebd26f91f558cd59a4bd57fff9119ee987) converts DEX to JAR, repairs bytecode and loads it on a JVM. Its WebView shim calls completion callbacks but returns null from JavaScript evaluation, while challenge handling can use a separate FlareSolverr dependency. That demonstrates both a sizeable compatibility subsystem and concrete semantic gaps. Embedding it would add another service/runtime, browser behavior, signing/update handling and security boundary on Windows and Linux. No measured arbitrary-extension compatibility rate was established; assigning a percentage would be invented. [ExtensionManager.kt](https://github.com/miwayomi/miwayomi/blob/a3a776ebd26f91f558cd59a4bd57fff9119ee987/server/src/main/kotlin/miwayomi/extension/ExtensionManager.kt), [WebView shim](https://github.com/miwayomi/miwayomi/blob/a3a776ebd26f91f558cd59a4bd57fff9119ee987/android-compat/src/main/kotlin/android/webkit/WebView.kt).

### Resume, identity and fidelity

Nuvio separates a playback video ID from the stored progress key, with movie and season/episode-derived forms and potentially provider-specific content IDs. Millisecond position/duration and item identity need verification against the exact Colosseum target. Titles and bare episode numbers are insufficient. [WatchProgressIdentity.kt](https://github.com/NuvioMedia/NuvioMobile/blob/b8801eb449cb065a102490c977a8ee3890a7f7c3/composeApp/src/commonMain/kotlin/com/nuvio/app/features/watchprogress/WatchProgressIdentity.kt), [SupabaseProgressSyncAdapter.kt](https://github.com/NuvioMedia/NuvioMobile/blob/b8801eb449cb065a102490c977a8ee3890a7f7c3/composeApp/src/commonMain/kotlin/com/nuvio/app/features/watching/sync/SupabaseProgressSyncAdapter.kt).

The inspected backend progress function throttles small changes around 15 seconds of position delta and 30 seconds of elapsed update time. Its update predicate can accept a stale incoming position when the delta condition qualifies. Watched state upserts one record per content/season/episode/profile; replay events cannot be reconstructed from that state. These semantics require deliberate merge handling and defeat naïve continuous mirroring. They are source-derived behavior, not observed corruption of a user's account.

Nuvio's Trakt progress import retains a percentage with zero original position/duration; its SIMKL projection also avoids inventing episode timecodes. Thus shared trackers can convey paused fractions, but cannot promise the original stream's exact resume second. Keep that limitation with the Continue feature. [TraktProgressRepository.kt](https://github.com/NuvioMedia/NuvioMobile/blob/b8801eb449cb065a102490c977a8ee3890a7f7c3/composeApp/src/commonMain/kotlin/com/nuvio/app/features/trakt/TraktProgressRepository.kt), [SimklProjections.kt](https://github.com/NuvioMedia/NuvioMobile/blob/b8801eb449cb065a102490c977a8ee3890a7f7c3/composeApp/src/commonMain/kotlin/com/nuvio/app/features/simkl/SimklProjections.kt).

### Export route and licensing

The backend defines `nuvio_account_backup`, version 1, account scope. It includes profile/library/progress/watched/add-on/plugin/collection/settings data while excluding sessions, device links, PIN hashes, tracker tokens and provider credentials. Its restore supports only full replacement, not merge. Never call that restore RPC as a Colosseum import mechanism or reproduce its destructive replace semantics. Parse an exported file locally and project only the explicitly admitted fields. [Official import script](https://github.com/NuvioMedia/self-host/blob/39ea2bd1bc71636127f9d797599c23b4236960c4/scripts/import-account.sh).

For comparison, [Nuvio-Account-Manager revision c122c44f86f3f9aa58ae742ae4abcc2f0ebba971](https://github.com/techuhak/Nuvio-Account-Manager/tree/c122c44f86f3f9aa58ae742ae4abcc2f0ebba971) contains a Stremio mapper, but it collapses watch count into a last-watched record, has removal/paging fidelity limitations and lacked a license file in the inspected snapshot. It is neither a dependency to copy nor evidence of lossless state interchange. The official apps are GPLv3, while the self-host repository has Apache-2.0 and dependency notices. Implement protocol/file parsing independently and retain any required notices; do not transplant GPL application classes or unlicensed mapper code into MIT Colosseum.

## Rejected approaches

- Embed Android, CloudStream or a DEX-to-JVM server merely to advertise repository support. This creates another runtime, update/distribution surface and sandbox obligation with no evidence of reliable arbitrary compatibility.
- Treat Phisher's 84 binary entries, publisher health status or same-repository hashes as proof of current source contracts, safety or playback health.
- Port historical StreamPlay v366/v529 or ship the bounded Arc 61 leaf and label it current v686 support; extract embedded secrets; silently send official API keys to historical mutable proxy services.
- Add browser automation, generic downloaded-JavaScript execution, remote deobfuscation services or extension-supplied local proxies as incidental conveniences for the first source adapter.
- Port Torrentio wrappers to duplicate the existing Stremio lane, or add TMDB/Wyzie work solely to claim StreamPlay progress.
- Convert tracker episode/chapter counts into arbitrary Continue fractions or local History/Activity; convert a partially watched episode into a completed count; infer rewatch cycles from one completion event.
- Require fake AniList refresh tokens, bundle a desktop client secret, reuse the MAL loopback listener without fragment handling, or describe local token deletion as confirmed remote revocation.
- Mirror Nuvio profiles/settings/provider secrets, read another running app's live persistence, call full-replace backup restore, or infer shared Stremio account state from common add-ons.
- Copy GPL application/provider logic or unlicensed migration code into MIT Colosseum without a compatible distribution decision. A language port alone does not settle provenance.
- Create another library, identity, history, progress, player, credential or extension owner. Adapt at the existing owners and preserve provenance and durable receipts.

# Biblio wave 3: visual recreation and verification

I replaced `demos/biblio.html` with a self-contained, 1280 × 720 HTML recreation of the Biblio world. It has an actual mouse-wheel-scrollable page and a thin scrollbar inside the fixed stage, the fixed five-pill world navigation (Tankoban, Biblio, Theatre, Universes, Feria), the top-right search/tracker/Device/wallpaper/window controls, and the fixed two-icon bottom-left glass taskbar. The Biblio pill is gold. It uses only inline CSS and JavaScript and relative local assets; it does not fetch any book art or information from the network. The stage uses the specified `../assets/cold-ripple.jpg` and `../assets/Fraunces-Regular.ttf`.

The hero uses the mock's locally available Project Hail Mary cover by default, with four manually selectable features, the Biblio kicker, author line, Read/Details preview actions, and four indicator dots. Immediately below is the glass Discover/Explore/Library tab bar. It docks just under the fixed top bar when the user scrolls past the hero. Each tab switches content in place, preserves a per-tab scroll position during the session, and supports keyboard Left/Right/Home/End tab navigation.

Discover includes a narrow source sidebar with an actual local Apple Books logo and a secondary local Biblio-book icon, the Books lens, the NOW BROWSING / Popular / Apple Books masthead, filter surface, and a seven-column catalogue of books with author lines at rest. Explore includes the collapsed-by-default row index, its working chevron to expand to 240 CSS pixels and retract to 52, hover/focus indicators, row-jump actions, and section-current tracking. Row labels and exact rule-based icons come from `RowIndexSidebar.qml`. Its inventory follows `BiblioExploreRules.js`: Top 10, Popular, Top Rated, New Releases, Trending, Most Read, Classics, then fixed Fiction, Nonfiction, Audience mosaics. Ranks use large translucent numerals. Book shelves have the QML's 130 × 182 covers, title and author captions, 16 px unranked spacing, and 28 px section gaps. Library is a simple retained mock collection with two staged books and progress bars. Read, Details, See All, Catalogue, Customize and shell actions expose offline-preview feedback; they do not purport to open the native app.

## Screenshot inspection and known visual differences

I visually opened all five specified app captures before implementation: `07-biblio.png`, `18-biblio-scrolled.png`, `23-biblio-explore-catalogue.png`, `23b-biblio-explore-catalogue-2.png`, and `25-biblio-book-page.png`. I also read the accepted `demos/feria.html` contract and the named QML components with read-only `git show master:qml/...`. The fifth screenshot is a separate book detail view, used as reference only, not included in the world demo.

The biggest unavoidable difference is the background. All running-app Biblio screenshots have a warm, colorful bridge-and-city wallpaper. The assignment explicitly requires the existing local `../assets/cold-ripple.jpg`, which is a monochrome lake/pier photograph, so I used that rather than borrowing screenshot pixels or inventing a replacement asset. Its different brightness and contrast also change how the glass looks.

The running app's featured title in `07-biblio.png` is Verity with its distinctive black/green cover. This title and cover are not in the initial mock's staged Biblio inventory; I did not copy the user's real library data. The initial feature is instead the mock's Project Hail Mary cover and the hero uses a hand-staged dark brown gradient rather than live art-derived tint.

The original mock holds ten book names, but only two covers as usable local files: Dune and Project Hail Mary. The other eight covers in `world-catalogue.js` are remote Apple image URLs, which the contract forbids. I made typographic CSS dust jackets for the other eight titles; these are deliberately not claimed to be authentic editions. Discover uses a repeated 32-card rotation of those ten staged books, while Explore rotates the same inventory across the shelves. Accordingly, the screenshots' large assortment of genuine colored book jackets and their user's specific titles cannot be matched. No screenshots were embedded, cropped, or reused.

The real Discover screenshot shows additional native sources and titles, whereas this offline mock carries only the local Apple Books icon and a generic second Biblio source. Actual native search, shelves customization, real book opening, ratings, catalogues, dynamic source menus, and backend state are intentionally outside a static, offline HTML demo. The screenshot is 1920 × 1008 at 150% scale, or 1280 × 672 CSS pixels; the mandated output is 1280 × 720, so the fixed bottom dock appears about 48 CSS pixels lower in the output than in the provided cropped app captures.

## QML versus screenshot observations and choices

`BiblioWorld.qml` declares Featured Carousel, Continue Reading, and then the three tabs. In `07-biblio.png`, the area between the featured hero and the tabs has no visible Continue Reading cards, so I collapsed that empty row, as the screenshot demands. I did not assume that the user's library or progress is actually empty.

`WorldPage.qml` establishes the 54 px board margin, 96 px scroll-viewport origin and 36 px layout rhythm; `FeaturedCarousel.qml` gives the 330 px hero; `WorldTabBar.qml` gives a 480 × 54 in-flow three-tab glass bar and a 390 × 46 compact docked bar. Those measured portions largely matched the screenshot. The main QML maintains internal scroll state for some retained pages, whereas this assignment requires one *real* outer vertical scroller; the HTML therefore uses a single `#viewport` scroll owner and stores per-tab offsets in JavaScript.

`DiscoverBrowser.qml` names a 132 px Biblio poster width and gallery 20 px horizontal gap, yet `18-biblio-scrolled.png` visibly shows seven across a 1092 px content column, whose stretched widths are around 139 px. I used a seven-column flexible grid, preserving 20 px gaps and author text beneath each image. The screenshot labels the source `Apple Books`; the older starting mock used `Biblio built-in catalogue`. I chose the screenshot's Apple Books text and actual local source icon rather than repeating the outdated label.

`RowIndexSidebar.qml` specifies a 12 px pin line, 52 px closed / 240 px open widths, 46 px rows, 4 px gaps, and regex-derived glyphs. At the requested deep Explore scroll, directly applying the nominal pin-line left the first star about 54 px too low relative to the screenshots. I used a `top:-42px` Explore rail sticky offset so the first star, the three-star sequence, clock and list glyphs line up with `23b-biblio-explore-catalogue-2.png`. This is a screenshot-first visual override of the nominal QML pin position, not a claim that the QML value itself changed. In the output the Trending and Most Read headers land at about y = 187 and y = 469 CSS pixels, close to the reference frame around y = 182 and y = 466.

`BiblioExplorePage.qml` loads up to 20 live native entries per rail and installed extension shelves when present. The initial offline mock has only ten staged book names and no safe local extension catalogue images. I used eight cards per house rail, ten for the ranked Top 10, and left out optional extension rows rather than inventing an installed provider. `BiblioBookRail.qml` author lines at rest, 8 px radii, 20 px serif headers and 13 px See All labels are implemented. The live Fiction/Nonfiction/Audience mosaics show catalogue-fed covers, whereas mine reuses the staged mock covers.
